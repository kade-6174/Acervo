# 管理者による標本の無効化・完全削除

管理トップの「標本管理」から対象を検索します。管理者roleとMFAの設定・認証が必要です。無効化・完全削除の確定時には直近のTOTPまたはパスキー再認証、標本番号の再入力、確認チェックが必要です。

## 無効化

誤登録などで標本の利用を止める場合は、対象の「無効化」を開き、表示された標本番号と対象内容を確認します。標本・履歴・写真は保持しますが、通常の検索・詳細・写真・編集・ラベル出力・CSVから除外されます。割当QRも無効になります。所蔵中・貸出中などの物理的な状態は変更しません。管理者の標本管理一覧では「無効」と表示されます。復旧操作は提供していません。

## 完全削除

無効化済みの標本だけに「完全削除」を表示します。標本、関連履歴、写真のDB行と写真ファイルを削除します。対象の標本番号と履歴・写真の件数を確認してください。この操作は取り消せません。

QRは無効状態のまま識別子を保持し、別の標本へ再利用できません。採番元も戻さないため、削除した標本番号は再利用しません。詳細・写真のURLは404となり、QRのURLは無効QRの警告を表示します。重要操作の監査記録は残ります。既存バックアップには保持期間中のデータが残るため、削除前のバックアップを復元するとその標本も戻ります。

## 写真ファイルの削除待ち

DBと写真ファイルは同時にコミットできないため、写真ファイルはDB確定後に削除します。失敗や処理中断があれば削除待ちをDBに残します。管理トップ・標本管理一覧に削除待ち件数を表示します。削除待ちの写真を通常画面から取得することはできません。

サーバー管理者は、アプリのLinuxホストでリポジトリのディレクトリへ移動し、採用している公開方式のコマンドを1行ずつ実行します。写真の保存パスや写真内容は表示しません。

対象ホスト: アプリのLinuxホスト。直接HTTPS構成:

```bash
docker compose -f compose.production.yaml -f compose.direct.yaml exec -T web python manage.py retry_photo_deletions
```

対象ホスト: アプリのLinuxホスト。Cloudflare Tunnel構成:

```bash
docker compose -f compose.production.yaml -f compose.cloudflare.yaml exec -T web python manage.py retry_photo_deletions
```

確認ポイント: 「完了」と「保留」の件数が表示され、保留0件なら終了コード0です。失敗が残る場合は終了コード1となり、削除待ちは保持されます。写真ボリュームの容量・書込み権限・接続を確認してから再実行してください。DBや写真ディレクトリを手動で一括削除する必要はありません。

## 画面での受入

削除してよい非機密の試験用標本を使用し、実データを対象にしないでください。以下の確認を行った端末・日時・結果を非公開の運用記録へ残します。

| 確認 | 期待結果 |
|---|---|
| member・MFA未完了のadminで管理URLへアクセス | 管理操作を拒否 |
| 確認画面でキャンセル、確認チェックなし、誤った標本番号 | データを変更しない |
| 試験標本を無効化 | 管理一覧に無効表示、通常の検索・詳細・写真・CSVから除外 |
| 無効化した標本のQRを読み取る | 標本情報を表示せず無効QRの警告 |
| 無効化済み試験標本を完全削除 | 標本と関連履歴・写真を削除し、QRは無効のまま |
| 監査ログを確認 | 実行者と操作種別を記録 |

実機受入、公開HTTPS、独立した空環境へのバックアップ復元は別の確認項目です。この機能の自動テスト成功だけでPhase 9全体や7C-LIVE-A・7C-LIVE-Bを完了扱いにはしません。
