# Step 7C-LIVE 実施前確認

この文書は、Acervoを実運用の公開環境へ導入する前に、設計責任者と運用者が承認する確認事項です。7C-LIVE-Aで公開基盤とMFAを受け入れ、標本機能実装後の7C-LIVE-Bで標本・写真と実データ復元を受け入れます。この文書の更新ではDNS、Tunnel、秘密値、本番ホスト、実アカウントは操作・記載しません。導入先固有の実値は、アクセス制限された[非公開運用台帳テンプレート](templates/PRIVATE_OPERATIONS_RUNBOOK.md)の複製先で管理します。

Acervoは1インスタンスを1組織が運用する汎用ソフトウェアです。直接HTTPSが標準で、Cloudflare Tunnelは任意です。公開方式、公開hostname、組織名、在籍ポリシーをアプリコードへ固定しません。具体的な生物班の例は[生物班向け導入・運用例](examples/KDF_BIOLOGY.md)を参照してください。

## 承認パッケージ（人による確定待ち）

次の全項目が人によって確定・承認されるまで、Step 7C-LIVEの外部操作を開始しません。承認記録と導入先固有の実値は、アクセス制限された非公開運用台帳の複製先だけで管理します。

### 公開設定

- [ ] 公開hostnameを確定した。最初のパスキー登録より前に確定し、`ACERVO_PUBLIC_BASE_URL`へHTTPS URLとして設定する。WebAuthn RP IDはこのhostnameから導出されるため、後からhostnameを変える場合は既存パスキーの再登録を計画する。
- [ ] `DJANGO_ALLOWED_HOSTS`は公開hostname、`DJANGO_CSRF_TRUSTED_ORIGINS`は同じHTTPS Originへ完全一致で設定する。
- [ ] 直接HTTPSまたはTunnel専用のどちらか一方を選んだ。共通基盤`compose.production.yaml`を単独起動せず、`compose.direct.yaml`と`compose.cloudflare.yaml`を同時に指定しない。
- [ ] `DJANGO_SECRET_KEY`、`ACERVO_MFA_FERNET_KEYS`、DB資格情報、Tunnel tokenを別々に生成・保管できる。これらをGit、ログ、コマンド履歴へ出さない運用手段を確認した。

### 責任者

- [ ] DNS責任者、Cloudflare Tunnel責任者、本番ホスト責任者、バックアップ責任者を確定した。
- [ ] 秘密鍵保管担当を確定し、初期管理者、継続運用管理者候補、緊急時の連絡先と引継ぎ方法を確定した。公開鍵を1本だけにする場合は、その鍵を失うと既存バックアップを復元できないリスクを承認した。

### バックアップ運用

- [ ] サーバー外の暗号化バックアップ保存先、各秘密鍵の相互に独立した保管場所、定期実行の時刻と実行主体を確定した。
- [ ] 成功・失敗を確認する担当者と頻度、空の復元試験先、四半期ごとの復元試験予定を確定した。
- [ ] 鍵紛失、漏えい、担当者交代時の更新手順を承認した。各`age`秘密鍵は単独で復号できる完全な鍵である。recipientを1本だけにする場合は、秘密鍵の紛失・破損で既存バックアップを復元できない。後継者の公開鍵を登録した後は、新規バックアップを複数recipientへ暗号化する。暗号化バックアップと秘密鍵を同じ場所に置かない。
- [ ] recipient変更時の扱いを確認した。新しいrecipient群で新規バックアップを作成し、旧recipientを外しても既存成果物の復号権限は失われないため、既存成果物の再暗号化または安全な廃棄を別途判断する。秘密分散、Shamir方式、二者承認機構はMVPに追加しない。

### 受入端末

- [ ] 対象スマートフォン・PCと各OS、対象ブラウザ、同期パスキープロバイダー、TOTPアプリを確定した。
- [ ] 非対応端末または未確認ブラウザの扱いを確定した。端末内パスキー、同期パスキー、TOTP、Recovery Codesの復旧経路を維持する。

学校回生方式を選ぶ導入先だけは、`ACERVO_ENROLLMENT_POLICY=school_cohort`と、年度開始月・日、基準年度、基準年度の1年生回生を設定します。一般組織は`none`を選べます。旧`ACERVO_BASE_THIRD_YEAR_COHORT`は本番起動時に拒否されます。

## 承認後の受入

以下は承認後にだけ、選択した公開方式で実施します。各項目が期待結果を満たさない場合は、次へ進みません。7C-LIVE-Aの成功は一般利用開始を意味しません。7C-LIVE-BはPhase 2〜5の実装と必須テストの成功後に実施します。

### 7C-LIVE-A: 公開基盤・MFA受入

1. 本番相当ホストに秘密値を安全に設定し、Compose設定、イメージ、migration、`check --deploy`、healthcheckを確認する。公開URL、Host、CSRF Origin、サイト名、組織名、在籍ポリシーを整合させ、秘密値を履歴・ログへ出さない。
2. 公開ポートと内部ネットワーク境界を確認する。直接HTTPSでは`proxy`だけが80/tcp、443/tcp、443/udpを公開し、Tunnel専用では全サービスのホスト公開ポートをゼロにする。`web`とPostgreSQLはCompose内部だけで到達可能である。
3. HTTPS、hostname、Secure Cookie、Host／Origin検証、転送ヘッダー信頼境界を確認する。直接HTTPSでは外部の転送ヘッダーを採用せず、Tunnel専用では信頼済み経路で正規化された`CF-Connecting-IP`だけを使う。
4. 非機密の試験用アカウントで、初期管理者の初回パスワード変更、TOTP、Recovery Codes、WebAuthn、passwordless passkeyを受け入れる。管理者MFAゲートがMFA未完了・古いMFA認証記録を拒否することを確認する。権限不足や認証失敗の経路も確認する。
5. 署名付き暗号化バックアップをサーバー外へ複製し、独立した空環境へ復元する。署名とチェックサムの検証、ログイン、管理者MFA、再起動後のDBと写真ボリュームの永続化を確認する。標本・写真データの表示確認は7C-LIVE-Bで行う。この段階が成功しても一般利用者へ公開しない。

### 7C-LIVE-B: 標本機能実装後の受入と限定運用後の実データ復元確認

1. Phase 2〜5の標本・QR・登録・詳細・保護写真の実装と、PostgreSQL上の必須テスト成功を確認する。代表的な非機密標本と写真を使い、未使用QRからの初回登録、登録確定時だけの採番、使用済みQRと検索結果からの詳細表示を確認する。未ログイン、権限不足、不正入力、競合、標本番号・DB連番IDの直入力による取得拒否、保護写真の直接URLでの未認証・権限不足拒否も確認する。
2. 非機密標本と写真を含む署名付き暗号化バックアップを別ホストへ保存し、独立した空環境へ復元する。ログイン、標本詳細、保護写真、管理者MFA、永続化を確認する。
3. 初期管理者だけで限定運用を開始し、実運用設定と初期データを含む署名付き暗号化バックアップを取得する。本番から独立し外部公開されていない空環境へ復元し、ログイン、標本詳細、保護写真、管理者MFA、永続化を再確認する。
4. 復元試験に使った秘密情報とデータを安全に処理し、成功後に一般利用開始の承認を得る。後方互換性のないmigration後の切戻しは旧アプリへの復帰ではなく、直前バックアップからの復元を使う。

Phase 10Aとして、署名付き暗号化バックアップと空環境復元の手順・CI統合検証は実装済みです。導入先の独立した検証環境では復元データによるDjangoビューの認証・管理画面と、再起動後のDB・写真用ボリューム保持を確認しています。実ブラウザ／HTTPS経路での復元後認証と、標本・写真の実データ復元受入は未確認です。CIの試験標本・写真による復元検査と実環境の受入はそれぞれ記録し、7C-LIVE-Aと7C-LIVE-Bの両方が成功するまでStep 7C-LIVE全体は完了扱いにしません。

## 中止条件

次のいずれかに該当したら、外部作業を中止し、原因と安全な復旧方法を確認してから再承認します。

- hostname、公開方式、責任者のいずれかが未確定である。
- 秘密情報がリポジトリ、ログ、コマンド履歴へ露出する可能性がある。
- バックアップと秘密鍵が同一障害領域にしか存在しない。
- 空でない復元先を上書きする可能性がある。
- 本番ポート境界が仕様と異なる、またはGunicornかPostgreSQLが外部公開される。
- 管理者MFAゲートが機能しない、または保護写真を未認証で取得できる。
- バックアップ、復号、チェックサム、空環境への復元のいずれかが成立しない。
- 実環境のPostgreSQLメジャーがバックアップまたは復元手順の前提と異なる。
- PostgreSQL上の必須テストまたは本番Compose検証が失敗する。
- 本番データを破壊する可能性があり、復元可能なバックアップがない。
- CI成功を実環境の復元試験の代替として扱おうとしている。
- 生物班固有の値を汎用コードへ固定する必要が生じる。
- `PROJECT_SPEC.md` と実装または文書に解消不能な矛盾がある。
