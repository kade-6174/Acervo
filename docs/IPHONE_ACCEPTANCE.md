# iPhoneでの登録・QR・更新確認

対象端末はiPhoneです。公開HTTPSの本番サイトで、削除してよい非機密の試験標本と、本番サイトが発行したQRを使います。端末・iOS・日時・Safari／ホーム画面アプリの別、結果を非公開運用台帳へ記録してください。パスワード、認証コード、Recovery Codesや実写真を記録へ貼り付けません。

## 更新した画面を開く

1. Safariで本番サイトを開き、必要ならログインします。
2. ページを再読み込みします。表示名が設定されたサイト名で、「Acervo」の固定表示がないことを確認します。
3. 標本登録を開き、分類欄に科・亜科・族・属・種が表示され、和名の候補を選べることを確認します。「別の分類を選択する」は表示しません。
4. ホーム画面に追加済みのアプリも開き直し、同じ画面を確認します。

内容別URLの静的資産を使う本番版では、画面の再取得後に新しいJavaScript・CSSを参照します。古い画面が残る場合は、Safariとホーム画面アプリのどちらか、再読み込み後も続くかを記録してください。サイトデータの一括削除は通常手順に含めません。

## 分類候補

1. すべての階級を空欄にし、各欄で全候補が表示されることを確認します。
2. 科を選び、下位欄がその科に属する候補だけになることを確認します。
3. 亜科・族・属を選び、選択したすべての上位階級に合う候補だけになることを確認します。候補は和名の五十音順です。
4. 科を別のものに変え、合わない下位選択が空欄へ戻ることを確認します。
5. 上位欄を空欄へ戻し、候補が再び広がることを確認します。亜科・族がない系統は、その欄を選ばずに属・種へ進めます。
6. 種を直接選んだ場合も、上位階級を強制入力されずに確認画面へ進めることを確認します。別系統の上位を併せて選んだ不整合な入力は受け付けません。

## 本番サイト発行QRの写真読取

1. 管理画面で本番サイト用QRを発行し、QR PDFの対象ラベルをスクリーンショットまたは写真としてiPhoneの「写真」に保存します。管理者の操作にはMFAが必要です。
2. QR読取画面の写真選択欄を押します。保存済み写真を選択でき、撮影画面だけへ進まないことを確認します。
3. 保存した本番サイト発行QRの画像を選びます。未使用QRなら標本登録、割当済みQRなら対象の標本詳細へ進むことを確認します。
4. 無効QRは利用不可と表示され、標本情報を開けないことを確認します。
5. 別サイト用QRは拒否されることを確認します。別サイトのテストQRを読めた結果で、本番サイト用QRの受入を完了にしません。
6. Safariとホーム画面アプリで同じ確認を行います。カメラ読取も、本番発行QRの実印刷を使って確認します。

同一サイトのUUIDv4 QR URLだけを許可する制限は維持します。読取に失敗した場合は、端末・アプリの別、表示された案内、画像が本番発行QRか、画像の向き・大きさを記録します。制限を緩めて受入を通しません。

## 試験標本の登録

未使用QRから非機密の試験標本を入力し、確認画面へ進みます。確認画面へ進むだけでは標本番号を消費しません。確定後に番号・分類・写真が詳細に表示され、同じQRを再読取するとその詳細へ進むことを確認します。ログアウト後に詳細・写真のURLへ直接アクセスしても内容を取得できないことを確認します。

試験標本の整理は、管理者が[標本管理手順](SPECIMEN_MANAGEMENT.md)に従って無効化・完全削除します。実データを整理対象へ混ぜません。

## 未確認項目の扱い

この手順の結果だけで7C-LIVE-A・7C-LIVE-B、Phase 1全体を完了にしません。独立した空環境への復元、実ブラウザのMFA、実データの標本・写真復元、再起動後の永続化などは[リリース確認表](OPERATIONS.md)と`PLAN.md`に従って別途記録します。Android向け実装はMVP内で、Android実機受入だけをMVP完成後へ残します。
